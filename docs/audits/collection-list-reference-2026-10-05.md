# Collection list page reference contract

Read-only reference: Shopify Spinel theme 166302089264, `/collections`. Development target: unpublished theme 144448127024 only.

Purpose: browse the store's collections through linked collection images and titles. The main resource section stays limited to `list-collections`. A dynamic shared Heading defaults to Collections list/H1; static Collection list owns the resource query, page size and grid. Its static shared Collection card has editable dynamic Title/Description/Button roles; its static shared Pagination owns native page links. There is no sort or load-more mode. Blank Custom collections means all store collections; a selected list uses its saved order and native pagination. Hidden titles/cards/pagination remain merchant choices. Missing images use collection outline placeholders; an empty store does not invent collection links.

Reference defaults: page width, left alignment, divider toggles off, composition gap40 desktop/30 mobile, scheme1, section padding70/90 with mobile override40/50. Grid has12 collections/page,3 desktop columns (2–6),1 mobile (1–2), column gaps12/8 and row gaps30/28. Card is landscape3:2, below image, left, child gap4/4, border0, inherited radius, no shadow, inherited color, content padding16/0/0/0. Title shows count, visual md/semanticH2, body/sm count and zero padding. Pagination Primary, inherited height, padding10/0.

Ownership: section owns width/alignment/surface/spacing/dividers; Collection list owns source/perpage/columns/gaps; shared card owns media/content/appearance; shared role blocks own typography/spacing; Shopify owns URLs/native pagination. Static slots are absent from block_order. Heading uses the current canonical display/xl/lg/md/sm/xs/custom scale independently from HTML Tag. Existing static card titles in editorial sections are preserved through a separate composition adapter that reuses the same render kernel. The shared card exposes explicit landscape_3_2/portrait_2_3 options for3:2/2:3 media, preserving saved landscape4:3/portrait4:5 options. This page selects landscape_3_2.

Responsive: integral columns at all viewports; desktop configured columns, mobile configured1/2. Shared page margins, typography, card radius, scheme/button/icon tokens remain authoritative. Tablet padding scales0.75; absent mobile override scales0.5. All page content is server-rendered; first-row images eagerly load, subsequent rows lazy load with layout-aware sizes. Pagination uses shared Heroicons and native Previous/Next URLs/current-page semantics.

Validation: schema, source selection/paginated resource accounting, hidden static slots, responsive grid, settings visibility, shared dependencies, scoped development upload, Theme Editor and storefront QA. No main/live upload, Git push or cross-repository sync is authorized.

## Implementation and local validation

Replaced the legacy all-collections markup in `sections/collections.liquid` while preserving the existing template main section ID/type. Added `_collections-list` as the fixed resource grid. The page reuses Heading, Collection card and its content roles, Pagination, native page-link snippet, component pagination styles and shared Heroicons. Collection card's new optional content/media parameters preserve existing editorial fixed-title/image loading behavior when absent; new explicit aspect-ratio options preserve existing ratio meanings. Pagination receives materialized native page links/count from the query-owning block and its one-page editor message is resource-neutral.

A read-only development pull showed the existing list template and all shared dependencies matched HEAD exactly; the template held only the legacy main section with empty settings. Uploaded only the six implementation files plus the shared page-link snippet LiquidDoc contract to theme144448127024 with `--nodelete`. No other configuration or theme files were overwritten. No Git push, live/main change or cross-repository sync was performed.

Initial runtime QA exposed Shopify's native restriction: `paginate collections_source` rejected an assigned alias. Fixed by using mutually exclusive direct `paginate collections` and `paginate block.settings.custom_collections` branches, both containing their own direct resource loop and forwarding the native paginate drop. The repeated small composition is deliberate: capture/snippet indirection must not move Theme Block rendering outside its native page query. Official [paginate documentation](https://shopify.dev/docs/api/liquid/tags/paginate) confirms collection-list settings support independent native pagination query parameters.

Local Liquid fixtures cover ordered custom resources, the blank-picker path, subsequent-page resource accounting, empty status, hidden card slots, first-row eager/later lazy media and saved static-slot ordering. They do not emulate Shopify query fetching or paginate eligibility; native browser QA is required for those behaviors. Shared blog/collection pagination regressions and new fixtures pass27/27. Theme Check reports zero errors and35 pre-existing warnings outside the changed scope; whitespace validation passes. Schema input IDs are unique, ranges/default steps valid and every changed setting has a Liquid/CSS consumer. Theme Block inventory151/300; shallow nesting and section capacity remain valid.

Port9292 has no listener and no preview watcher was started.

Native custom-source QA found a second platform scope constraint: the paginate drop lazily reevaluates its `block.settings` path when read inside the child Pagination block. Materializing the native page count and capturing shared page-link markup in the parent query scope (passing its block into the snippet) prevents the child settings from replacing that resource owner. Shared Pagination accepts the materialized content while retaining ownership of its style, height and padding. The new lazy-drop regression throws if the child attempts to read the parent's query data and passes with materialized native links.
